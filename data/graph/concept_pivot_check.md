# 컨셉 전환 데이터 점검 (2026-07-27)

## 배경

새 화면 흐름의 핵심은 "쟁점별로 금감원이 판단 시 중요하게 본 요인들"을 뽑아
사용자에게 **확인·준비 항목**으로 제시하는 것이다. 이 컨셉이 성립하려면 그래프가
쟁점별로 (1) 표본이 충분하고 (2) 그 표본에서 반복적으로 나타나는 판단 요인이
3개 이상 뽑혀야 한다. 화면을 바꾸기 전에 이 전제를 먼저 데이터로 확인한다.

모든 집계는 `(Case)-[hi:HAS_ISSUE]->(Issue)` 관계에서 **`hi.result = '인정'`인
사례만** 대상으로 했다(쟁점이 인정된 사례들의 공통 요인을 보는 것이 목적이므로
불인정·기각 사례를 섞으면 "판단에 유리했던 요인"이 희석된다).

## 방법

Neo4j에 아래 4개 쿼리를 실행했다(조회 전용, 그래프 변경 없음):

1. 전체 Issue 노드 목록 + 쟁점별 전체 사례 수 / 인정 사례 수
2. 쟁점별(인정 사례만) `HAS_FACTOR` 요인 빈도
3. 쟁점별(인정 사례만) case-level `CITES` 법조항 빈도 — 사람이 확정한 정적
   `GOVERNED_BY`(`ISSUE_LAW_MAP`)와 별개로, LLM이 각 사례 원문에서 추출한 raw 인용
4. 쟁점별(인정 사례만) `CITES_PRECEDENT` 판례 빈도

## 결과 1 — 그래프에 존재하는 Issue는 15개뿐, DOCUMENT_MAP은 17개 키

`backend/main.py`의 `DOCUMENT_MAP`은 16개 쟁점 + `기타`로 총 17개 키를 갖고
있지만, 그래프의 `Issue` 노드는 **15개**뿐이다.

| DOCUMENT_MAP 키 | 그래프 상태 |
|---|---|
| 우대금리_미적용 | **Issue 노드 자체가 그래프에 없음** (0건) |
| 금리인하요구권 | **Issue 노드 자체가 그래프에 없음** (0건) |
| 적정성원칙_위반 | Issue 노드는 있으나 `HAS_ISSUE` 사례 0건 |

세 쟁점 모두 1차 스코프(은행·중소서민 + 금융투자 180건, `data/SCOPE.md` 참조)에
해당 유형 사례가 아예 없었던 것으로 보인다. 즉 지금 메뉴에 이 3개를 넣어도
"확인·준비 항목"은커녕 유사 사례 검색조차 항상 빈 결과를 반환한다.

## 결과 3 — 쟁점별 판단 요인 (인정 사례 기준)

"판단 요인으로 뽑을 수 있다"의 기준을 **n≥5**로 잡았다(시뮬레이터의
`TIER_REFERENCE` 하한과 동일한 기준 재사용 — 이미 이 값을 "노이즈가 아니라고
믿을 수 있는 최소 표본"으로 검증한 바 있음). 이 기준으로 인정 사례 내에서
factor n≥5인 것이 3개 이상인 쟁점만 추렸다.

| 쟁점 | 인정 사례 | n≥5 factor 수 | 상위 factor (n) |
|---|---:|---:|---|
| **설명의무_위반** | 59 | **10** | 신청인_주의소홀(39), 투자경험_다수(32), 서류_자필미기재(19), 고령자(17), 금융취약계층(13), 최초투자(12), 모니터링콜_부실(8), 예적금목적_방문(7), 고액투자자(6), 기타(6) |
| **적합성원칙_위반** | 28 | **10** | 신청인_주의소홀(14), 투자경험_다수(12), 서류_자필미기재(12), 최초투자(9), 고령자(9), 모니터링콜_부실(8), 금융취약계층(7), 예적금목적_방문(6), 고액투자자(5), 기타(5) |
| **부당권유** | 34 | **6** | 신청인_주의소홀(26), 투자경험_다수(23), 최초투자(8), 고령자(7), 금융취약계층(6), 서류_자필미기재(5) |
| **불완전판매_기타** | 12 | **5** | 투자경험_다수(8), 신청인_주의소홀(7), 고령자(6), 서류_자필미기재(6), 금융취약계층(5) |
| 임의처리_무단거래 | 29 | 1 | 신청인_주의소홀(19) — 나머지는 최초투자(4), 기타(3), 투자경험_다수(3), 고령자(3), 금융취약계층(3) 등 n<5 |
| 담보_보증분쟁 | 17 | 0 | 서류_자필미기재(2), 기타(1) |
| 약관해석_분쟁 | 13 | 0 | 전부 n=1 |
| 예금지급_분쟁 | 9 | 0 | 신청인_주의소홀(4)이 최대, n<5 |
| 착오송금 | 5 | 0 | 신청인_주의소홀(1) |
| 전산장애 / 수수료_비용분쟁 / 보이스피싱_피해보상 / 중도해지_불이익 | 각 1~2 | 0 | 표본 자체가 5 미만 |

**"실질적으로 강한" 쟁점은 4개**: 설명의무_위반, 적합성원칙_위반, 부당권유,
불완전판매_기타. 넷 다 투자성 상품(펀드·신탁 등) 불완전판매 계열이며, Factor
온톨로지 자체가 애초에 이 계열을 겨냥해 설계돼 있었다는 걸 재확인시켜준다.

임의처리_무단거래는 인정 사례가 29건으로 표본은 적지 않지만, 현재 Factor
온톨로지(투자경험/고령자/서류미기재 등 "투자권유 국면" 요인)가 "무단거래가
있었는가/누가 승인했는가"를 다투는 이 쟁점의 실제 쟁점 구조와 안 맞아서 신청인_
주의소홀 외에는 거의 잡히지 않는다. 이건 요인 회수 실패라기보다 **온톨로지
공백**(무단거래 전용 factor가 애초에 정의된 적 없음)에 가깝다 — 재추출로 해결될
문제가 아니라 새 factor 타입 설계가 먼저 필요하므로 이번 스코프에서는 다루지
않는다.

## 결과 4 — 법조항/판례 raw 인용(CITES/CITES_PRECEDENT)은 근거로 쓰기엔 너무 파편화됨

4개 강한 쟁점 모두에서 raw `CITES`는 쟁점당 60~110개의 서로 다른 조항 문자열이
나왔고, 최빈값도 인정 사례의 15~30% 커버에 그친다(예: 설명의무_위반 59건 중
가장 많이 인용된 민법 제110조도 19건). 판례도 마찬가지로 최빈 판례가 인정
사례의 20% 안팎만 커버한다. 게다가 같은 조항이 "舊자본시장법 제47조 제1항" /
"자본시장법 제47조 제1항", "판결" 접미사 유무, 띄어쓰기 차이로 여러 문자열로
쪼개져 있어 표면적 빈도보다 실제 겹침은 더 크다.

→ 이는 기존에 이미 내린 결정(`graph_search.law_articles_for_issues`가 raw
`CITES`가 아니라 사람이 확정한 정적 `GOVERNED_BY`만 쓰는 것)이 여전히 맞다는
뜻이다. raw 인용 데이터는 "판단요인 확인·준비 항목" 화면의 근거로 직접 쓰기엔
너무 파편화돼 있다 — 새 화면에서도 법조항은 지금처럼 `GOVERNED_BY` 4건
(설명의무_위반→금소법 제19조, 적합성원칙_위반→제17조, 적정성원칙_위반→제18조,
부당권유→제21조) 그대로 쓰는 게 맞다. 다만 적정성원칙_위반은 결과 1에서 확인했듯
사례가 0건이라 이 매핑 자체가 화면에 노출될 일이 없다.

## 결과 5 — 쟁점→요인→서류 사슬 점검 (DOCUMENT_MAP 대조)

4개 강한 쟁점의 상위 factor와 기존 `DOCUMENT_MAP` 서류 목록을 대조한 결과:

| 쟁점 | 상위 factor → 대응 서류 | 정합성 |
|---|---|---|
| 설명의무_위반 | 서류_자필미기재→가입신청서/투자자정보확인서, 모니터링콜_부실→상담 녹취록, 고령자·금융취약계층→(입증용) 투자자정보확인서·상품설명서 | 양호 — 이미 있는 4개 서류가 상위 factor 절반 이상을 직접 뒷받침 |
| 적합성원칙_위반 | 서류_자필미기재→투자자정보확인서, 모니터링콜_부실→상담 녹취록 | 양호 — 동일 4개 서류로 커버 |
| 부당권유 | 신청인_주의소홀/투자경험_다수는 간접적(녹취록으로 반박), 손실보전각서 서류가 이 쟁점 특유의 factor(문서화에 없는 "손실보전 약정")를 커버 | 양호하나 factor 자체가 서류로 직접 증명되는 성격은 약함 |
| 불완전판매_기타 | 고령자·서류_자필미기재→투자자정보확인서/가입신청서 | 양호 |

정적 매핑표라 그래프 엣지로 명시된 "Factor→Document" 관계는 없지만, 4개 강한
쟁점에 한해서는 사람이 짠 현재 서류 목록이 실제 factor 분포와 실질적으로
어긋나지 않는다. 반대로 임의처리_무단거래의 서류 목록(계좌·카드 거래내역서,
본인 미승인 확인서, 고객센터 접수증)은 결과 3에서 드러난 factor 공백과 맞물려
— 애초에 이 쟁점은 factor 기반 "확인·준비 항목" UI보다 "사건 발생 증빙 서류"
안내 쪽에 더 가깝다는 뜻으로 읽힌다.

## 결론

1. **유형 선택 메뉴에 올릴 수 있는(요인 기반 확인·준비 항목 UI 지원) 쟁점은
   4개**: 설명의무_위반, 적합성원칙_위반, 부당권유, 불완전판매_기타.
   전부 투자성 상품 불완전판매 계열이고, 각각 factor n≥5가 5~10개씩 나온다.
2. `DOCUMENT_MAP`의 우대금리_미적용/금리인하요구권/적정성원칙_위반 3개 키는
   그래프에 대응 사례가 0건이라 새 메뉴(및 현재 메뉴)에서 제외해야 한다 —
   선택해도 항상 빈 결과만 나온다.
3. 임의처리_무단거래(인정 29건)·담보_보증분쟁(17건)·약관해석_분쟁(13건)·
   예금지급_분쟁(9건)은 사례 자체는 있으니 **유사 사례 검색/배상비율 분포는
   지금처럼 지원**하되, factor 표본이 3개 이상 뽑히지 않으므로 "판단요인
   확인·준비 항목" UI는 이번 스코프에서는 붙이지 않는 게 맞다.
4. 착오송금·전산장애·수수료_비용분쟁·보이스피싱_피해보상·중도해지_불이익은
   인정 사례가 1~5건뿐이라 어떤 형태의 통계 기반 기능도 근거가 되기엔 표본이
   부족하다.
5. 법조항 근거는 raw `CITES`가 아니라 기존 `GOVERNED_BY`(4건 고정 매핑)를
   그대로 쓰는 게 맞다는 기존 결정이 재확인됐다.

이번 점검은 조회만 수행했고 그래프·JSON·코드 변경은 없다. 화면 흐름 확정은
사용자 검토 후 별도로 진행한다.
